Design Thoughts

  1. DRY (Don't Repeat Yourself)
    • Avoid code duplication.
    • Reuse code through functions, classes, or modules.
  2. KISS (Keep It Simple, Stupid)
    • Design systems as simply as possible.
    • Avoid unnecessary complexity.
  3. Easy to Understand
    • Use clear names.
    • Write comments that explain why, not what.
  4. Separation of Concerns
    • Divide a program into distinct functional areas.
  5. High Cohesion & Low Coupling
    • Group related functionality together.
    • Minimise dependencies between components.
  6. Package-Oriented Design
    • Organise code into small, cohesive packages.
    • Keep public APIs minimal.
  7. Minimalism in Public APIs
    • Define small, focused interfaces.
    • Export only what is necessary.
  8. Encapsulation
    • Hide internal state behind methods.
  9. Composition Over Inheritance
    • Prefer composing behaviour over subclassing.
  10. Dependency Injection
    • Provide dependencies externally.
    • Improves testability and flexibility.
  11. Avoid Global State
    • Pass dependencies explicitly.
  12. Idiomatic Error Handling
    • Handle errors first.
  13. Narrow Scope
    • Short variable lifetimes improve optimisation.
    • Reduces cognitive load.
    • Reduces shadowing risk.
  14. Efficient Code
    • Avoid unnecessary copies.
    • Pass large data by reference.
