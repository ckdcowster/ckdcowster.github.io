Go Best Practices

  • Functions
    Validate inputs.

  • Comma ok/error Idiom
    Prefer to return error in functions, and check for NOT ok and deal with the error.

  • If - Else
    It's idiomatic to return early and avoid nesting.
    If a block ends with return, continue, or break, you don't need an else.

  • Constants
    Put constants into global space.

  • Sets
    Use anonymous structs for sets: map[int]struct{}.

  • Strings
    Use strings.Builder to create complex strings (more efficient).
    Use strings.Fields to remove all white space including leading & trailing.

  • Pointers
    You need to modify the caller's data.
    The value is large or expensive to copy.
    You're building reference based structures i.e., trees, graphs, linked lists, caches, and other node-based designs.
    Avoid:Creating a value and then taking its address inside loops.
    Prefer:Prefer: allocating the pointer directly. e.g., child := &Node{ID: r.ID}

  • Slices
    Prefer append when the final size is unknown or the slice grows dynamically.
    If the final size is known (or can be tightly estimated), use make with a length or capacity hint.
    Prefer indexing when the slice length is known and fixed.
    copy() copies up to the length of the destination slice, not its capacity.

  • Switch
    • Prefer map[rune]:
      • For efficient lookup and updates.
    • Use For State Machines:
      • Replace if/else clauses.
  • Variable Declaration
    • Use := (short variable declaration) when:
      • You're declaring and initializing a variable in a local scope (e.g., inside a function).
      • The type can be inferred from the value.
    • Use var when:
      • You need to declare a variable without initializing it.
      • You're declaring a package-level variable.
      • You want to specify the type explicitly.
      • You're using a zero value intentionally.
    Group variables that relate to the same subsystem, error category, or configuration within var ( )
