Functions

  • Validate inputs.

Comma ok / error idiom

  • Prefer to return error in functions, and check for NOT ok and deal with the error.

If / Else

  • It's idiomatic to return early and avoid nesting.
  • If a block ends with return, continue, or break, you don't need an else.

Constants

  • Put constants into global space.

Sets

  • Use anonymous structs for sets: map[int]struct{}.

Strings

  • Use strings.Builder to create complex strings (more efficient).
  • Use strings.Fields to remove all white space including leading & trailing.

Pointers

  • You need to modify the caller's data.
  • The value is large or expensive to copy.
  • You're building reference-based structures (trees, graphs, linked lists, caches).
  • Avoid: Creating a value and then taking its address inside loops.
  • Prefer: Allocating the pointer directly, e.g. child := &Node{ID: r.ID}

Slices

  • Prefer append when the final size is unknown or grows dynamically.
  • If the final size is known, use make with a length or capacity hint.
  • Prefer indexing when the slice length is known and fixed.
  • copy() copies up to the length of the destination slice, not its capacity.

Switch

  • Prefer map[rune] for efficient lookup and updates.
  • Use switch for state machines to replace if/else chains.

Variable Declaration

  • Use := when declaring and initializing a variable in local scope.
  • Use var when declaring without initialization or when specifying type explicitly.
  • Group related variables inside var ( ).

Booleans Are Too Ambiguous for Complex Logic

  • Use named constants instead of boolean values.
  • Consider enums or structs for more expressive logic.
type ActionResult int
const (
    ActionContinue ActionResult = iota
    ActionFinished
    ActionInvalid
    ActionError
)
