Go Best Practices

  1. Functions
    • Validate inputs.
  2. Comma ok / error idiom
    • Prefer returning an error and checking for NOT ok.
  3. If / Else
    • Return early to avoid nesting.
    • If a block ends with return/continue/break, you don’t need an else.
  4. Constants
    • Put constants at package level.
  5. Sets
    • Use map[int]struct{} for sets.
  6. Strings
    • Use strings.Builder for efficient concatenation.
    • Use strings.Fields to remove whitespace.
  7. Pointers
    • Use when modifying caller data.
    • Use when values are large or expensive to copy.
    • Use for reference-based structures (trees, graphs, lists).
    • Avoid taking addresses of loop variables.
    • Prefer allocating pointers directly.
  8. Slices
    • Use append when size is unknown.
    • Use make() when size is known.
    • Prefer indexing when length is fixed.
    • copy() copies up to destination length.
  9. Switch
    • Use map[rune] for efficient lookup.
    • Use switch for state machines.
  10. Variable Declaration
    • Use := for local inferred declarations.
    • Use var for explicit types or zero values.
    • Group related variables in var ( ).
  11. Booleans Are Too Ambiguous
    • Use enums or named constants instead of booleans.
    
type ActionResult int
const (
    ActionContinue ActionResult = iota
    ActionFinished
    ActionInvalid
    ActionError
)
