Go Design Patterns

  1. Constructor Functions Return Pointers
    • When creating a new struct, Go constructors commonly return a pointer.
    • type Cache struct {
    data map[string]string
}

func NewCache() *Cache {
    return &Cache{
        data: make(map[string]string),
    }
}
    • Returning a pointer avoids copying large structs and lets methods modify the shared instance. It is a common convention, not a requirement for every constructor.
  2. Initialize Maps with make
    • A nil map can be read, but must be initialized before writing to it.
    • counts := make(map[string]int)
counts["go"]++
  3. WaitGroup Around Goroutines
    • Use a sync.WaitGroup to wait for a group of goroutines to finish.
    • var wg sync.WaitGroup
wg.Add(1)

go func() {
    defer wg.Done()
    doWork()
}()

wg.Wait()
    • Call Add before starting the goroutine, and pair each added count with a call to Done.
  4. Anonymous Function Wrapper for Goroutines
    • Pass loop values as function arguments so each goroutine receives the value for its iteration.
    • for i := 0; i < 5; i++ {
    go func(id int) {
        fmt.Println(id)
    }(i)
}
  5. Context for Cancellation
    • Long-running operations should check their context and stop when it is cancelled.
    • func Run(ctx context.Context) {
    for {
        select {
        case <-ctx.Done():
            return
        default:
            doWork()
        }
    }
}
    • Pass context.Context down the call chain, for example: func Process(ctx context.Context).
  6. Channel and Select
    • Use select to wait on channel operations and cancellation together.
    • select {
case msg := <-ch:
    handle(msg)

case <-ctx.Done():
    return
}
  7. Defer for Cleanup
    • Schedule cleanup with defer immediately after successfully acquiring a resource.
    • file, err := os.Open(name)
if err != nil {
    return err
}
defer file.Close()
    • The same pattern applies to unlocking a mutex and marking a WaitGroup task done: mu.Lock(); defer mu.Unlock() and defer wg.Done().
  8. Tuple Assignment
    • Use multiple assignment for clear swaps and related updates.
    • a, b = b, a

for b != 0 {
    a, b = b, a%b
}
    • This is common in swaps, accumulator updates, and Euclid's GCD algorithm.
  9. Error Early, Return Early
    • Handle errors first and keep the successful path unindented.
    • if err != nil {
    return err
}

doSomething()
    • This is often called the happy-path style.
  10. Avoid Accidental Shadowing
    • Short declarations inside nested scopes can create a new variable instead of updating an outer one.
    • var res Result
var err error

for {
    r, e := opener()
    if e == nil {
        res = r
        break
    }
    err = e
}
    • Use distinct names when a short declaration could hide an outer variable.
  11. Plain Slice as a Stack
    • A slice is usually enough for stack behavior; create a dedicated type only when it adds meaningful behavior.
    • var stack []rune

stack = append(stack, ch)
top := stack[len(stack)-1]
stack = stack[:len(stack)-1]
    • When you can estimate the needed capacity, preallocate it: stack := make([]rune, 0, 100).
  12. Range When Iterating Collections
    • Use range to iterate over values, or ignore values you do not need with _.
    • for _, value := range values {
    fmt.Println(value)
}

for idx := range values {
    fmt.Println(idx)
}
